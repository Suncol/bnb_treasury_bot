**Scope:** 旧库识别/兼容读取或必要迁移、首次有效观察、离线状态诊断、重启恢复与操作说明。优先复用现有存储，不要求新建数据库或重新初始化账户。

**Acceptance criteria:**

- [x] 使用基准版本生成的数据库夹具，覆盖空闲但有外部未解释差额、开放 GTC、部分成交、撤单 UNKNOWN、下单 UNKNOWN、三种方向划转待结算及已结束保护事件。
- [x] 空闲旧库在当前账户及订单观察满足条件时可接受新基线，无需补齐全部历史来源；旧库中的来源解释错误仅在确认没有本机结算责任后退出执行门禁。
- [x] 存在开放/未决/待结算本机操作时，保留其身份、原基线、成交唯一键、窗口和相关证据；升级成功不代表操作成功，也不自动关闭严格窗口。
- [x] 旧操作缺失必要身份或恢复基线时，状态明确指出缺失内容并保持阻断；不能由迁移过程建立新余额基线替它结算。
- [x] 旧库中因预测进入的 URGENT 通过固定阈值及现有退出缓冲、连续确认收敛；无效观察和重启不能提前消耗确认次数。
- [x] 外部余额接受、意图落盘、请求已发送但无回执、回执入库、结算完成及窗口关闭边界分别注入事务失败和重启；不重复下单/划转，不丢失敞口，不把窗口意外切为空闲。
- [x] 跨重启保留滚动预算和未决预占、急跌事件累计买入、切片截止时间、资金到账续作/重规划续作、资金耗尽屏障和持久化退避。
- [x] 已退休本机订单出现矛盾迟到成交时，仍保留原本机归属并进入恢复/诊断；不得重分类为外部变化，也不得无声重复累计。
- [x] 重复回执和重复启动不重复改变预算、保护累计或基线代次。已有确定失败/未发送操作不能被升级改为成功，也不能改变真正 UNKNOWN 的恢复语义。
- [x] 离线状态查看不连接交易所、不推进模型、不创建新库；清晰展示空闲外部观察、严格窗口、本机待结算、当前数据无效及缺失历史证据的区别。
- [x] 用户说明包含阶段一限制、升级时保留的操作责任和原有恢复方式；保留仍用于严格窗口的成交导入、人工核验和显式初始化入口。
- [x] 以真实持久化存储运行上述升级和重启用例，记录写请求次数及唯一身份；测试不使用生产凭证或真实交易请求。

**Verification:** 从旧版本夹具连续执行“升级 → 首次读取 → 故障注入 → 重启 → 补齐证据 → 恢复运行”，比较操作身份、已发送请求数、余额准入、预算和保护累计。给出可重复的离线验证记录。

**Out of scope:** 自动修复缺失财务证据、批量重置 UNKNOWN、删除旧审计数据、迁移到新数据库、改变只读状态命令的副作用边界。
