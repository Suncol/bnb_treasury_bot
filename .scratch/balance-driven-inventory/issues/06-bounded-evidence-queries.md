# 06: 按结算责任查询历史，消除无关的长窗口扫描

**Blocked by:** 04：空闲期解除完整收入审计门槛，保留本机结算证明。

**Status:** done

**What to build:** 空闲库存检查只读取当前账户、相关活动订单和必要预算数据；仍开放的严格窗口及账户预算继续读取所需历史，不再为已取消的消耗预测或无决策用途的保证金指标持续扫描长历史。仍开放的本机 GTC 即使暂无新增成交，也属于有核对责任的严格窗口。

**Context:** 放宽门禁后若仍无条件执行旧历史查询，网络延迟、分页和退避仍会拖住补货。本票交付可验证的请求范围收缩，同时保留严格结算、迟到证据恢复和本机操作的查询恢复能力。

**Scope:** 以业务用途规划历史读取范围、合并重叠需求、保留分页/唯一身份和持久化恢复。没有用途的历史指标可以不计算；无需新增指标线程、调度平台或完整外部资产审计服务。

**Acceptance criteria:**

- [x] 在无本机严格窗口的空闲周期中，不查询消耗率历史、24h 保证金证明或外部交易对成交；当前账户、相关活动买单和预算需要的划转读取仍按规则执行。
- [x] 严格窗口的证据范围由所有仍可能改变余额的本机操作及待结算责任的必要基线、已验证前缀和失败证明区间决定；不得只保留固定 24h/49h，丢失 48h、72h 或更久未决操作的恢复能力。
- [x] 本机 GTC 已受理、当前已知成交均结算，但订单仍开放时，继续保留严格窗口所需完整核对；注入外部余额变化但缺回执时仍阻断。不能因未知/待结算列表暂时为空而停查、接受差额或切换到空闲查询路径。
- [x] 对多个订单/划转的重叠证据需求合并读取，并按身份去重；不能因减少请求而省略双向划转、实际成交费用或当前证明所需的外部活动。
- [x] 旧 24h 指标基线不再扩大执行查询范围；新的接受基线是当前证明边界，不能为修复无关旧指标回放到其之前。
- [x] 收入接口无永久完结水位这一限制保留：严格窗口内的新执行批次、缓存期限、资产变化和失败区间仍使用所需完整复核；不能仅凭最近一次非空响应或净额守恒永久宣称完整。
- [x] 长期未决超过交易所保留范围时保持具体的恢复阻断，不把被截断的成功响应认定为证据完整；原有认证归档/人工核验边界保持。
- [x] 按用户新决定，资金不足退出不依赖外部支出或冻结归因；空闲续作不额外查询这些成交或其他交易对活动订单。BNB 活动订单、冻结/可用余额与预算观察仍保留。
- [x] 保留配置中仍服务严格窗口的外部交易对、导入工具、原始回执和历史表；本票不以“减少查询”为由整体删除它们。
- [x] 迟到回执、重叠时间边界、同毫秒多条记录、重复页、相互抵消收入以及存储失败仍按原唯一身份和证据规则处理；失败不推进覆盖范围或重新授予执行资格。
- [x] 慢分页期间保留优先保护检查；账户/行情过期、保护动作、时钟回退和资格失效仍废弃旧候选。429/418 与持久化退避不能因查询变少而失效。
- [x] 用请求计数、区间和可控虚拟时钟验证空闲无冗余扫描、严格窗口所需证据完整、慢读取不会给旧观察续期；不以本机毫秒基准宣称生产响应保证。
- [x] 更新设计中的查询用途、触发条件和已知限制；通过相关历史、执行边界、重启、保护性撤单及离线补仓流程回归。

**Verification:** 对空闲、开放 GTC、本机划转待结算、超过 72h 未决及已结算续作的当前资金不足等场景记录调用序列和范围。空闲路径应无无关历史调用，资金不足退出不依赖外部支出/冻结归因；严格路径在缺证据时继续阻断，补齐后恢复且不重复操作。

**Out of scope:** 完全删除历史账本、删除严格窗口中的收入接口、放宽重试/未知状态、以资金不足退出声明资金去向、承诺共享账户外部活动永不阻断。
