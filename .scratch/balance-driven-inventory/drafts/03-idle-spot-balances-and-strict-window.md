# 03: 空闲期接受外部现货余额，操作期间固定严格核对窗口

**Blocked by:** 01：分离执行准入原因，保持当前行为。

**Status:** draft — 待拆分与发布确认；尚未发布。

**What to build:** 机器人没有仍可能改变余额的本机操作时，人工或其他策略造成的现货 BNB/稳定币增减可以作为当前库存使用，不再要求解释每笔来源；启动本机操作后，继续使用固定证据边界严格核对，直至相关操作完整结束。

**Context:** “没有本机待结算”不能只理解为未知请求列表为空。已经受理的开放 GTC 仍可能成交，即使目前没有已知新成交，也必须留在严格核对窗口。本票先放宽现货差额，合约收入审计暂保留现状，形成可独立验收的纵向交付。

**Scope:** 串行读取、现货基线接受、意图持久化、订单/划转恢复、窗口关闭与状态诊断。优先复用现有活动操作日志及订单退休边界；只有现有数据不能可靠表达时才增加必要持久化信息。

**Acceptance criteria:**

- [ ] 严格窗口从发送新订单/划转请求前的意图持久化开始，覆盖提交未知、开放/部分成交 GTC、未终态 IOC、撤单过程以及终态后仍待成交或余额覆盖的操作。
- [ ] 只有本机订单按固定身份确认终态、累计成交及实际成本/费用完整、相关余额覆盖完成，且划转和撤单均已恢复，才允许关闭窗口；活动订单列表为空或请求被受理不能单独证明完成。
- [ ] 窗口存在只表示继续采用严格核对，不等于禁止一切正常动作。证据完整时仍可按原门禁挂后续分层订单、回划已确认 BNB；不得为获得宽松观察资格自动撤掉正常 GTC。
- [ ] 在本机窗口关闭、当前账户及订单观察有效、没有已知相关外部在途划转，且原合约收入/余额证明与历史门禁均通过时，现货 BNB/稳定币的外部增加或减少可以更新库存基线，无需构造对应外部成交或入金记录。不得借更新包含合约字段的共享检查点跳过原合约证明。
- [ ] 总余额、可用余额与冻结余额分别保留；本交易对外部 BUY 仍计入经济总敞口且不由机器人撤销。其他交易对的监控范围不在本票中扩大。
- [ ] 过期/未来时间/非有限金额、接口间矛盾、前后订单视图变化、累计成交缺明细或已知相关外部 PENDING/UNKNOWN 划转时，不接受新基线；外部在途不得伪装为本机请求身份。
- [ ] 注入“本机 GTC 余额先更新，但两次订单视图和成交记录均迟到”的场景，开放本机订单使窗口保持严格，差额不能被当作外部输入吸收；回执补齐后按唯一身份仅核算一次。
- [ ] 接受外部变化与开启下一操作串行进行；新意图绑定最终验证账户、证据边界及基线代次，并与必须同步的续作/切片状态原子持久化后才发送。事务失败时外部写请求数为零。
- [ ] 窗口中的外部活动造成差额时，保留原严格核对和修复方式；不能覆盖基线、清除 balance_pending、伪造费用或通过等候/重复读数推定结算。
- [ ] 接受外部余额只记录“库存观察已接受”，不生成本机成交或已成功划转，不改变急跌毛买入累计、预算或真实操作身份。
- [ ] 新接受基线必须成为现货严格核对的回放边界。合约证明选取更早锚点时，不能让现货重放跨越这个边界；迟到回执无法证明是否已包含在新基线时保留记录并阻断相关窗口，不能直接重放、丢弃或吸收。
- [ ] 已退休本机订单出现矛盾迟到成交时，仍识别为本机责任并进入恢复，阻止将其变化接受为外部输入；不能等到升级验收票才增加这项保护。
- [ ] 重启保留窗口和基线；旧库存在开放本机订单或未决操作时，缺少新字段默认采用严格路径。缺失必要旧基线时阻断，不用当前余额修复成成功。
- [ ] 最终读取改变余额、冻结量或相关订单需求时，废弃旧候选再规划；保留当前版本的执行前时效、风险、模式及批次失效检查。
- [ ] 同步设计和术语，明确阶段一限制：开放本机 GTC 存续期间，外部活动仍可能阻断；本票没有提供跨接口因果版本或增强原有结算证明能力。

**Verification:** 在合约侧原有证明可通过的夹具中，分别演示空闲外部现货入金/支出后完成下一笔规划、提交及严格结算，以及同样变化发生在 GTC/UNKNOWN/单侧到账窗口内时持续阻断。覆盖旧合约回放锚点、跨新基线迟到回执，以及意图前、发送后及回执入库失败后的重启。

**Out of scope:** 放宽合约收入证明、改变初始账户绑定和初始化流程、删除外部成交导入工具、自动认领无 tranId 的未知划转、改变资金到账续作退出规则。
