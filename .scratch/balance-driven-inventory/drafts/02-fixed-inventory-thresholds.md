# 02: 仅按固定库存阈值决定补货紧迫度

**Blocked by:** None (can start immediately)。

**Status:** draft — 待拆分与发布确认；尚未发布。

**What to build:** 库存补货的启动、紧急升级和收尾只消费已确认的当前库存及已有状态规则，不再因为历史消耗率或预计耗尽时间改变动作。默认阈值保持 25 / 28 / 32 / 40 BNB。

**Context:** 用户已确认取消消耗速度对紧急状态的影响。现有预测在需要补货时可把尚高于下限的库存升级到 URGENT；本票移除这项行为，保留其他状态规则。

**Scope:** 从纯策略输入到主循环决策、持久化状态、重启恢复和状态说明形成完整变更。可以兼容读取旧字段，但不能仅在一个调用入口把消耗率写成零来掩盖仍存在的策略分支。

**Acceptance criteria:**

- [ ] 在相同当前余额、订单、既有业务状态和风控输入下，历史消耗率为零、很大或不可获得时，候选状态、最终状态以及买入/划转计划一致。
- [ ] IDLE 且合约库存恰好为 B_alert 时保持 IDLE；低于 B_alert 且高于 B_low 时，仍通过原有连续有效库存周期确认启动普通补货。
- [ ] 合约库存小于或等于 B_low 时立即进入 URGENT；仅预测六小时内耗尽不再触发 URGENT。
- [ ] 已启动的普通补仓在 B_alert 至 B_target 之间继续 ACCUMULATE，不因为越过预警线提前结束。
- [ ] URGENT 退出保留 B_low + 1 的缓冲和原有连续确认。旧库因预测进入的 URGENT 按新阈值及原确认机制收敛，不重置运行态或继续消费旧预测结果。
- [ ] 保留达到目标、达到 B_high、以及距目标严格小于最小可执行回划量时的立即收尾。默认配置下恰好 31.9 BNB 不因“小于 0.1”规则收尾，超过 31.9 才适用该容差。
- [ ] 存量 WATCH 按原迁移/连续确认规则进入普通补仓；不新增另一套补仓轮次或状态开关。
- [ ] 观察无效、操作未决或结算未完时仍冻结库存状态、确认计数和成功库存时间。固定阈值不绕过数据与结算门禁。
- [ ] 新决策不再输出以预测耗尽时间为行动依据的原因；旧持久化枚举可兼容读取，缺失指标明确为不可用，不伪造零消耗率。
- [ ] 急跌保护、分层价格、现货保留量、回划规则、账户级预算和全部 USD 调出硬 veto 保持原义；URGENT 不获得额外风控豁免。
- [ ] 设计、状态说明及用户文档明确记录取消预测升级的代价；离线测试同时覆盖纯策略入口、实际库存周期、阈值精确边界和旧 URGENT 重启。

**Verification:** 使用同一条库存路径分别提供零消耗率、极高消耗率和缺失消耗统计窗口，其他原有结算/收入证据保持相同且充分，比较完整动作序列；另验证 25、26、28、31.9、略高于 31.9、32、40 BNB 边界。

**Out of scope:** 本票不单独取消全账户收入审计；不实现净消耗速度、真实手续费速度、动态阈值或新的调资冷却参数。
