# 01: 分离执行准入原因，保持当前行为

**Blocked by:** None (can start immediately)。

**Status:** draft — 待拆分与发布确认；尚未发布。

**What to build:** 让运行状态、库存规划和直接执行对同一次观察给出一致、可区分的准入原因：当前观察无效、本机操作未决、资产待结算、历史诊断不可用。先建立后续简化所需的边界，本票完成时原有允许与阻断结果保持不变。

**Context:** 基于 codex/p1-implementation 的 dc8f3f3。当前余额差额会被编码为待处理订单，历史保证金证明失败也会被编码为账户观察不一致。这使后续放宽规则难以精确限定。

**Scope:** 在现有串行编排、对账入口和执行边界内引入明确的结果与原因；不拆进程，不引入通用工作流框架，不一次性重写整个对账器。

**Acceptance criteria:**

- [ ] 同一有效账户观察下，分别注入未知下单、已确认但待结算划转、纯外部余额差额和历史保证金证明失败；诊断能区分原因，不再把所有失败描述为存在待处理订单。
- [ ] 观察有效性、操作身份/状态、结算证据、历史指标可用性分别表达；本票仍由兼容准入规则组合，保持旧版的新增操作允许/阻断结果。
- [ ] 已受理且余额已覆盖的开放 GTC，与提交结果未知的订单保持不同语义；前者仍按原规则计入经济总敞口并管理，后者仍禁止新增操作。
- [ ] 库存周期推进、候选计数持久化、资金续作、直接执行使用同一准入解释，不出现主循环禁止而直接调用可以执行的旁路。
- [ ] 保留执行批次的身份、失效和重新验证规则。保护性撤单、观察变化、时钟回退及批次结束后，迟到读取不能重新授予旧批次执行资格；资格不跨重启沿用。
- [ ] 保留最终账户有效期、运行模式、急跌状态、候选需求、原行情及动态过滤器时效检查。刷新账户不能给旧候选或旧行情续期。
- [ ] 无效库存观察仍不推进成功库存时间、确认计数或切片；保护性撤单继续在必要的身份与退避约束下运行。
- [ ] 新结果格式可兼容现存持久化运行态；不得清空 UNKNOWN、待结算标记、预算预占或保护事件累计量。
- [ ] 状态输出与日志使用一致术语；更新领域术语表和设计中的职责说明，并明确本票没有放宽余额证明要求。
- [ ] 通过真实主循环、执行器和持久化存储的离线组合用例验证以上行为；不只测试结果对象的构造或字段映射。

**Verification:** 对同一组有效账户/未知订单/迟到余额/历史证明失败输入，比较重构前后的动作、状态推进和持久化结果；允许诊断更精确，但交易行为保持相同。

**Out of scope:** 接受外部差额、删除收入审计、改变库存阈值、调整预算、放宽资金到账续作退出条件。
